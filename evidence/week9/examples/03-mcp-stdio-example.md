# 03 STDIO MCP 真实样本 — 填写示例

> 用途：演示 STDIO 传输 MCP 的留档格式。命名前缀必须是 `mcp-stdio-*`。
> 建议用一个真实本地 MCP Server（如文件系统类）作为样本；Fixture 不算真实样本。

## 测试项与结果记录格式

| # | 测试项 | 操作 | 结果 | 记录要点 |
|---|---|---|---|---|
| 1 | 连接 | 配置并启动 STDIO MCP | ✅ | 连接成功、无超时 |
| 2 | Tool Catalog | 查看工具目录 | ✅ | 工具数量与名称正确 |
| 3 | 成功调用 | 至少调用一次工具 | ✅ | 工具名与返回内容 |
| 4 | 取消或超时 | 长调用中取消 | ✅ | 取消后无僵尸进程 |
| 5 | 断开重连 | 杀掉子进程后重连 | ✅ | 重连成功、目录恢复 |
| 6 | 不自动重放 | 制造一次失败调用 | ✅ | 失败调用不被重放 |

## 留档正文示例

```
2026-09-XX 16:00  连接：STDIO MCP 启动成功，进程树正常。
2026-09-XX 16:01  目录：枚举到 12 个工具，名称与 Server 定义一致。
2026-09-XX 16:03  调用：read_file 成功返回内容。
2026-09-XX 16:05  取消：长任务取消后子进程退出，无残留句柄。
2026-09-XX 16:07  重连：kill 子进程后应用自动重连，目录再次枚举成功。
2026-09-XX 16:09  重放检查：失败调用未自动重发，replayedCalls 计数为 0。
结论：PASSED
```

## 对应 user-evidence.json 片段

```json
{
  "transport": "STDIO",
  "status": "passed",
  "replayedCalls": 0,
  "evidenceId": "ev_9ab0ff13e2c7"
}
```

> ⚠️ 两个导入器硬校验：`transport` 必须精确写 `STDIO`（另一条写 `STREAMABLE_HTTP`）；
> `replayedCalls` 必须为 `0`，非 0 直接失败。
> JSON 中不要写 MCP Server 的绝对路径或机器名。
