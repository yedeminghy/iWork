# 05 Skill 真实验证 — 填写示例

> 用途：演示一期保留的真实 Skill 验证留档格式。命名前缀必须是 `skill-*`。

## 验证项与结果记录格式

| # | 验证项 | 操作 | 结果 | 记录要点 |
|---|---|---|---|---|
| 1 | 发现 | Skill 列表中能看到一期保留 Skill | ✅ | 名称与描述 |
| 2 | 激活 | 触发激活 | ✅ | 激活无报错 |
| 3 | 按需读取资源 | 触发资源加载 | ✅ | 资源内容正确 |
| 4 | 审批边界 | 触发需审批动作 | ✅ | 弹出审批、拒绝后不执行 |

## 留档正文示例

```
2026-09-XX 18:00  发现：列表显示 1 个一期保留 Skill，名称/描述正确。
2026-09-XX 18:02  激活：激活成功，状态图标变化。
2026-09-XX 18:04  资源：按需加载参考文档成功，内容与磁盘一致。
2026-09-XX 18:06  审批：脚本执行前弹出审批；拒绝后动作未执行、无副作用。
结论：PASSED
```

## 对应 user-evidence.json 片段

```json
{
  "skills": {
    "status": "passed",
    "evidenceId": "ev_2c6d7e8091b4"
  }
}
```

> 注意：skills 是**单个对象**（不是数组），整项只填一条。
> JSON 中不要写 Skill 的绝对路径。
